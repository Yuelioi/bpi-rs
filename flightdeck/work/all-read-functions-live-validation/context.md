# 上下文

本 Work 中“函数”指 crate 对外暴露、会向 Bilibili 发出网络请求的 endpoint/client 方法，不包含纯数据 getter、参数 builder、序列化辅助函数和内部 probe 实现。

用户明确要求测试所有非 action 操作函数。安全边界以实际远端副作用为准：只允许 public-read、authenticated-read、private-read；禁止 mutating、spending、login-session 以及任何可能改变点赞、投币、收藏、关注、评论、弹幕、账号、历史进度或其他远端状态的方法。名称位于 `action.rs` 但只读取状态的函数需测试；名称不含 action 但有副作用的函数必须排除。

账号使用仓库根目录 `account.toml` 的匿名、`normal`、`vip` 三档。不得输出或提交 Cookie、账号 ID、私有响应体、播放 URL 或签名参数。批量 live 输出仅放在 Git 忽略的 `target/`；持久报告只记录函数名、契约、身份、HTTP/API/解析分类和脱敏统计。

“已测试”要求函数有实际 live 请求证据；仅编译、离线 fixture 或同 endpoint 的另一函数通过不算。对无需或不支持某身份的函数，应记录不适用理由。契约预期漂移不能算通过，必须用不带陈旧 expectation 的只读调用取得响应，并验证成功载荷模型或稳定错误分类。

“有代表性”不能机械等同于每个函数固定 3 个样本。应先根据模块领域和历史 API 演进识别会改变 JSON/二进制结构的等价类，再为每个重要等价类选择多个真实样本。例如动态需区分年代、文字/图片/视频/OPUS/转发、嵌套层级、已删除或权限状态；番剧需区分老番/中期/新番、连载/完结、免费/VIP、单季/多季、正片/特别篇等。单例账号状态接口无法按内容取样时，应明确标记不适用，并用身份/状态/重复观测代替。

每个等价类默认至少 3 个样本；若上游稀有、下线或权限限制导致不足，必须记录搜索范围、实际样本数和限制，不得用一个样本冒充覆盖。年代分界和类型分类以实际响应字段为准，不只依赖标题关键词。

当前工作树含上一 Work 的 Issue #13 修复、测试与用户原有 Flightdeck 升级改动，必须全部保留。
